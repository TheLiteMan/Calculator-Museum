1.1. Общие сведения

    Наименование проекта: Виртуальный музей вычислительной техники с интерактивными эмуляторами.

    Область применения: Образовательная среда, популяризация истории информатики и вычислительной техники, интерактивное обучение принципам работы исторических счетных механизмов.

    Целевая аудитория: Студенты профильных ИТ-специальностей, школьники, увлекающиеся программированием, историки науки.

1.2. Назначение и цели создания системы

    Цель проекта: Создание масштабируемой веб-платформы, позволяющей пользователям изучать исторические этапы развития ЭВМ и тестировать логику работы оригинальных устройств прямо в браузере с помощью серверной математической эмуляции.

    Задачи проекта:

        Разработка отказоустойчивого бэкенда на фреймворке Flask.

        Реализация реляционной структуры базы данных на базе SQLAlchemy (SQLite).

        Создание программных движков-эмуляторов для 4-х классов устройств: Римский абак, Суммирующая машина Паскаля, Арифмометр Однера, Калькулятор «Электроника Б3-34».

        Обеспечение безопасности пользовательских данных посредством хеширования паролей (Werkzeug).

        Разработка REST-API интерфейса для интеграции со сторонними автоматизированными системами.

1.3. Требования к функциональным характеристикам

Система должна быть разделена на логические подсистемы:

    Подсистема авторизации и аутентификации:

        Регистрация пользователей с валидацией email, уникальности имени и проверкой совпадения паролей.

        Сессионный вход в систему с использованием механизма flask-login.

        Безопасное хранение учётных записей в БД с использованием криптографических хешей PBKDF2 (или аналогичных, генерируемых Werkzeug).

    Подсистема интерактивных экспонатов (Витрина):

        Вывод списка доступных экспонатов с возможностью фильтрации по типу симулятора и полнотекстового поиска по названию.

        Динамический подсчет количества просмотров каждого экспоната при переходе на его страницу.

    Подсистема серверной симуляции:

        Обработка входящих AJAX (JSON) запросов, передающих параметры действий пользователя (сдвиг каретки, поворот колеса, ввод числа в стек).

        Вычисление нового состояния устройства на сервере и возврат детализированного пошагового лога истории операций.

    Подсистема отзывов и обратной связи:

        Возможность для авторизованных пользователей выставлять оценки экспонатам (от 1 до 5) и оставлять текстовые рецензии.

    Подсистема администрирования:

        Форма добавления новых экспонатов в каталог музея (доступна пользователю с ID=1).

    Служебные подсистемы (Автономные):

        Модуль аналитики: Разбор файлов серверных логов, автоматическое определение кодировки (UTF-8 / CP1251), подсчет ошибок, выявление сетевых атак, генерация текстового отчета.

        Модуль резервного копирования: Архивация базы данных в ZIP-формат, ротация архивных копий (хранение не более 5 последних файлов).

        Модуль сидирования: Программное первичное наполнение базы данных валидными тестовыми сущностями.

1.4. Требования к надежности и окружению

    Приложение должно корректно обрабатывать ошибки типа 404 (Ресурс не найден) и 500 (Внутренняя ошибка сервера), перенаправляя пользователя на специализированные HTML-страницы и фиксируя сбои в журнале museum_system.log.

    База данных должна автоматически изолировать транзакции с помощью сессий SQLAlchemy. При сбоях сидирования или записи отзывов должен производиться автоматический откат (rollback).
